Epic In Progress · KAN-8

Engineering Memory & Confidence Calibration

Confidence scores were being written to a table nothing ever read. This epic closed the loop: a real endpoint that checks whether an agent's confidence actually predicts human approval — and now, whether a specific prompt version quietly broke that relationship.

✓ KAN-23 implemented, tested, documented ⏸ KAN-24 deferred — retention policy needs a product decision ⏸ KAN-25 deferred — threshold tuning needs real production data

Headline finding

ROADMAP.md's own risk register names this exact gap as a hard blocker past Phase 2: "Confidence scores become decorative (unchecked against outcomes)." The write path (workflow_service._record_confidence_calibration) was already real — every workflow approve/reject decision was being logged. The read path didn't exist. There was no way, anywhere in the product, to ask "does this agent's confidence score mean anything?" — until now.

02How Calibration Now Flows

Every workflow approve/reject decision already wrote a row per agent step. The new endpoint is the first thing that reads them back.

Human approves/rejects→ ConfidenceCalibration row written→ outer-joined against AgentStep.prompt_version→ grouped per agent, per version→ GET /calibration/summary

03The Miscalibration Flag — Tested Both Ways

A version is flagged only when it has enough decisions to mean something AND its approval rate has genuinely drifted from its agent's overall rate — both conditions verified directly in test_calibration_api.py.
